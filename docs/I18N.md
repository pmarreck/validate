# Internationalization (i18n)

`validate` ships its entire user-facing surface (CLI help, status labels,
summaries, error/warning messages, format descriptions) translated into a
canonical set of **50 locales**, in lockstep with the sibling `dirtree` tool.

## Phase: **enforce**

The UI surface is stable, so the project is in the *enforce* phase:

- Every translatable string is a field in a **no-default Zig struct**
  (`Strings` in `src/core/i18n/strings.zig`). A locale file that omits any field
  fails to compile — the build is the completeness check. There is **no silent
  fallback to English**.
- The `Locale` dispatch switches in `mod.zig` are **exhaustive**: adding a
  locale to the `Locale` enum forces a matching arm in every dispatch table or
  the build breaks.
- CLI argument and environment-variable alias maps are merged at **comptime**
  across all 50 locales. A same-name → **different-arg** mapping is a hard
  `@compileError`; same-name → same-arg dedupes silently. (This guard caught a
  real cross-locale collision in the fleet: Indonesian `--hanya` "only" vs
  Hausa `--hanya` "path".)
- Errors are **bilingual**: the localized message is followed by the English
  original in parentheses with a `(search for: "...")` hint, so a user hitting
  an error in their language can still search the English text.

## Selection rationale

This is **not** a top-50-by-speakers list. It pairs high-computer-penetration
languages with deliberately under-served ones (Hausa, Amharic, Yoruba, Igbo,
Filipino) on a "seed adoption where English penetration is thin" rationale.
The set is kept identical across the tool fleet (validate, dirtree, …) so
coverage is consistent.

## Locale-code parsing

`Locale.fromString` (in `mod.zig`) is a **longest-match-with-boundary** parser,
not a fixed-width prefix slice:

- Matches each known code case-insensitively, requiring the match to end at a
  separator (`_`/`-`/`.`) or end-of-string. This stops `fil` from being
  shadowed by `fi`, and makes `zh_hant` reachable (a naive `s[0..2]` made every
  `zh*` resolve to Simplified).
- Folds region/script suffixes: `de_DE`, `en-GB`, `pt_BR.UTF-8`, `zh_Hant`.
- Generic Chinese without an explicit script subtag defaults to Simplified;
  only the historically-Traditional regions (`zh_TW`/`zh_HK`/`zh_MO`) fold to
  Traditional.

## Selecting a locale

- CLI: `--lang <code>` (e.g. `--lang fr`). Locale-code *values* are universal
  ISO codes (never translated); the `--lang` *flag name* is aliased per locale.
- Env: `VALIDATE_LANG` → `LANG`/`LC_ALL`/`LC_MESSAGES`. `--lang` overrides env.
- Default fallback: `en`.

## File layout

```
src/core/i18n/
  ├── strings.zig      # Strings/FormatDescriptions/ErrorMap struct definitions
  ├── cli_aliases.zig  # CliAliases / EnvAliases struct definitions
  ├── mod.zig          # Locale enum, fromString parser, dispatch, alias maps
  ├── en.zig           # canonical English
  └── <code>.zig       # one per locale × 50
```

(The Turkish locale file is `tr.zig`, imported as `tr_locale` since `tr` is a
reserved-ish identifier in the enum, where it appears as `@"tr"`.)

## Adding / changing strings

Add the field to `Strings` (or the relevant struct) in `strings.zig`, then add the
translation to **all 50** locale files. The build will not pass until every
locale is complete — that is the enforcement mechanism, by design.
